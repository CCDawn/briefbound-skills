# Creative Method Guide

默认入口是 `../SKILL.md`。只读本轮选中的方法，不把整份指南变成输出模板。

## 目录

- 通用准备与七种创意方法
- 两方法例外、深度评估与停止规则

## 通用准备

先写出四项内部信息：

- `Stage`：GENERATE / EXPAND / SELECT / UNBLOCK / SUBVERT / REFINE / SYNTHESIZE / NAMING；
- `Situation`：具体在做什么、为谁、发生在什么场景；
- `Constraint`：时间、成本、能力、媒介、规则或不能改变的边界；
- `Tension`：用户同时想要但目前互相冲突的两件事。

没有约束时，优先从已有上下文提取，不用一串问题把创意工作退回给用户。

## 约束碰撞

适用：从零生成，但已有场景或限制。

1. 选两个真实材料，例如用户行为与技术限制、业务目标与反常数据。
2. 问“如果两者必须由同一个机制同时满足，会出现什么？”
3. 生成具体交互、流程、对象或规则，不生成抽象愿景。
4. 删除只用了其中一个材料的候选。

好结果示例结构：`当 <触发> 时，<对象> 通过 <机制> 改变 <结果>`。

## 机制变异

适用：已有一个可用方向，需要真正不同的变体。

一次只改变一个维度：

- 用户：谁发起、谁受益、谁决定；
- 触发：主动、自动、阈值、事件或周期；
- 媒介：页面、消息、实体、声音、后台规则；
- 尺度：单人、团队、组织、网络；
- 反馈：即时、延迟、公开、私密、可逆；
- 所有权：用户控制、系统建议、共同确认。

每个变体必须说明“改变了哪个维度”和“因此出现了什么新行为”。

## 事前验尸与反向检验

适用：多个方案需要选择。

1. 假设每个方案六个月后失败。
2. 写出最可能的具体失败原因，而不是泛称“执行不到位”。
3. 判断失败是否能低成本预防、尽早发现或几乎不可逆。
4. 用失败结构选方案；不要把所有项压成一个没有解释力的平均分。

输出可以只给一个结论和一个保留备选。

## 反转

适用：卡住、重复或默认假设过强。

1. 写出当前默认：`必须 X 才能 Y`。
2. 暂时反转：`禁止 X，仍要 Y` 或 `让 Y 先发生，再补 X`。
3. 找到反转后仍合理的部分。
4. 把它翻译回现实方案，保留新机制，移除纯噱头。

## 挑衅约束

适用：用户明确要求更怪、更意外或更不常规。

1. 提出 3 个故意不合理但与问题相关的命题。
2. 对每个命题问“它若成立，需要什么条件？”
3. 从条件中提取可实现的机制。
4. 至少保留一个现在就能小规模尝试的版本。

不要直接把荒谬命题当最终答案。

## 矛盾求解

适用：方向存在明确冲突，例如更自动但又要更多控制。

依次尝试：

- 按时间分层：先自动，关键点再确认；
- 按对象分层：低风险自动，高风险人工；
- 按空间分层：局部自由，全局约束；
- 按状态分层：默认简洁，需要时展开；
- 改反馈：先预览、可撤销或渐进承诺。

最终要说明冲突如何被重新安排，而不是声称“两者兼得”。

## 聚类命名

适用：大量访谈、笔记、点子或观察需要形成新主题。

1. 按行为或因果关系聚类，不按相同关键词机械分组。
2. 找每组共同机制、一个异常项和一个未被满足的需求。
3. 用能指导行动的短语命名主题。
4. 若异常项改变整体解释，把它单独提升为候选主题。

## 命名锻造

适用：需要产品、机制、研究概念或现象名称。

先写出：核心机制、关键张力、希望留下的记忆、禁止造成的误解。再从以下路径选一条：

- 机制直述：直接说它怎样工作；
- 张力组合：把两个冲突词压成新关系；
- 结果隐喻：借用一个与运行方式相似的具体对象；
- 新词组合：只有普通词无法准确表达时才造词。

每个名称说明构成、传达内容和误解风险。名字不能替代薄弱概念。

## 两方法例外

只有单一方法确实无法覆盖互相冲突的信号时组合两个，例如：

- 先用事前验尸选择，再用矛盾求解修正胜出方案；
- 先用挑衅约束打破常规，再用约束碰撞落回现实；
- 先聚类命名理解材料，再用约束碰撞生成方案。

最多两个，分别说明作用。不要恢复为 3-5 个算子流水线。

## 深度对抗评估

只有用户明确要求时才使用 `role-deck.md`。选择 2-3 个与风险直接相关的视角，每个只回答一个问题：最强支持证据、最可能失败点、最小验证。不要角色扮演长对话。

## 停止规则

- 用户选中一个方向：停止继续发散，进入深化或实现。
- 新候选只是在改名字：停止，回到机制差异。
- 连续候选不再增加新机制：切换方法一次；仍无变化则说明上下文缺口。
- 已有一个明显胜出且用户只要决定：直接给结论，不为格式凑数量。
