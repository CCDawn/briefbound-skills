# BRT Output Forms

仅在需显示对齐、handoff、自然闸门或破坏性确认时使用；SILENT/MICRO 不套模板。

## ALIGN

```text
需求对齐:
- 我理解的结果: ...
- 我准备做: ...
- 不包含: ...
- 完成证据: ...
- 最需要纠偏: ...
默认推进: ...
```

`HIGH/MEDIUM` 可默认推进；触发 `Alignment Value Gate` 时等待用户回复“按推荐”或纠正选项。

## LOW Collaborative Calibration

先说明理解、依据和错判点，一次提出 2-4 个相关问题：

```text
1. <高影响问题>
   推荐/理由: ...
   其他选择: ...
   错判影响: ...
```

提问前先摘要已查到的项目惯例；只问共同决定可执行契约且证据不能回答的问题。可回复“按推荐”或纠正编号；选项必须有行为差异。

## 意外问题讨论

仅用于契约外意外：

```text
意外问题: <证据>
影响: <契约变化>
推荐: <路径/理由>
等待: <已停止写入；安全诊断>
请回复: 按推荐 / <调整>
```

原契约内可安全、可逆恢复的问题直接处理并简报；否则停止受影响写入，不扩大范围，确认后更新契约并继续。

## BLOCKED

```text
当前阻塞: <原因和影响>
已确认: <证据>
恢复路径: <可执行方案>
需要你确认: <一个不可约问题>
```

## 方案或交接

只保留会被下一执行者使用的字段：目标与非目标、owning surface、关键顺序/决策、保护边界、验证、风险、Next Action。没有真实拆分就不输出 Task Graph；没有持久状态就不输出 Ledger。

## 多动作队列

```text
执行顺序:
1. <动作> [SAFE_DIRECT/PLAN_THEN_EXECUTE/DEFERRED/BLOCKED]；证据；完成条件
```

已有执行许可时连续推进 `SAFE_DIRECT`；仅在 BLOCKED、真实取舍或高风险授权处停下。

## UI 预览预审

`PREVIEW_REQUIRED` 是正式 UI 写入前的自然闸门：

```text
预览已就绪:
- 状态: WAITING_USER_REVIEW
- 预览网页: <local URL>
- 代表截图: <desktop/mobile>
- 覆盖: <主路径、状态与视口>
- 模拟/未验证: <真实缺口>
- 正式代码: 尚未修改
请回复: APPROVED / REVISE <反馈> / ABANDON
```

只有用户明确 `APPROVED` 才继续正式实现；`REVISE` 只修改隔离预览，`ABANDON` 停止该方向。UI Review 的 `READY_FOR_USER_APPROVAL` 不能代替用户批准。

## 破坏性确认

说明具体对象、不可逆影响、恢复/备份状态，并要求用户输入明确确认词。不要把普通提交、低风险编辑或可逆清理包装成破坏性菜单。

## 完成

```text
已完成: <行为结果>
验证: <命令/检查与结果>
剩余风险: <无或真实缺口>
下一步建议: <一个具体动作>
```

`下一步建议` 是最后一行；只有自然闸门才提供 2-3 个具体选项。
