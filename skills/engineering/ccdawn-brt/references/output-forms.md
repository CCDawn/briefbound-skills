# BRT Output Forms

仅用于对齐、handoff、自然闸门或破坏性确认；SILENT/MICRO 不套模板。复杂术语只在影响判断或操作时解释。

## ALIGN

```text
需求对齐:
- 我理解的结果: ...
- 完成证据: ...
- 最需要纠偏: ...
默认推进: ...
```

`HIGH/MEDIUM` 可推进；触发 `Alignment Value Gate` 时等待用户回复“按推荐”或纠正。

## LOW Collaborative Calibration

内部区分 `MISSING_CONTEXT / PRODUCT_FORK`，不把枚举当用户标题。前者先查证；后者一次提出 2-4 个问题：

```text
我理解你要的结果是: ...
我这样判断，是因为: ...
1. <高影响问题>
   我建议: ...，因为 ...
   换一种做法会: ...
   如果理解有误，可能: ...
请回复“按建议”或“按推荐”，也可以直接纠正编号。
```

提问前先摘要已查到的项目惯例；本地可发现的内容先查，只问证据不能回答且会改变契约的问题。

## 意外问题讨论

仅用于契约外意外：

```text
我发现了一个之前没预料到的问题: <证据>
它会影响: <行为、范围、数据/API、安全或验收的变化>
我建议: <路径/理由>
我已经暂停: <受影响写入；仍可继续的安全诊断>
请回复: 按建议 / 按推荐 / <调整>
```

原契约内可安全、可逆恢复的问题直接处理；否则停止受影响写入，确认后更新契约。

## BLOCKED

```text
现在无法继续: <原因和影响>
已经确认: <证据>
可以这样恢复: <可执行方案>
需要你决定: <一个不可约问题>
```

## 方案或交接

只保留下个执行者会使用的目标、surface、关键决策、保护边界、验证、风险和 Next Action。无真实拆分不输出 Task Graph；无持久状态不输出 Ledger。

## 多动作队列

```text
执行顺序:
1. <动作> [SAFE_DIRECT/PLAN_THEN_EXECUTE/DEFERRED/BLOCKED]；证据；完成条件
```

已有执行许可时连续推进 `SAFE_DIRECT`；仅在 BLOCKED、真实取舍或高风险授权处停下。

## UI 预览预审

`PREVIEW_REQUIRED` 是正式 UI 写入前的自然闸门：

```text
预览已就绪:
- 状态: WAITING_USER_REVIEW
- 预览网页: <local URL>
- 代表截图: <desktop/mobile>
- 覆盖: <主路径、状态与视口>
- 模拟/未验证: <真实缺口>
- 正式代码: 尚未修改
请回复: APPROVED / REVISE <反馈> / ABANDON
```

仅用户明确 `APPROVED` 后正式实现；`REVISE` 只改预览，`ABANDON` 停止。`READY_FOR_USER_APPROVAL` 不能代替用户批准。

## 破坏性确认

说明对象、不可逆影响和恢复状态，要求确认词；普通低风险操作不套此菜单。

## 完成

```text
已完成: <行为结果>
我是这样确认的: <命令/检查与结果>
还需注意: <无或真实缺口>
下一步建议: <一个具体动作>
```

`下一步建议` 是最后一行；只有自然闸门才提供 2-3 个具体选项。
